## Mathematical boundary

For `c0=d_c0*z`, the adapter applies

```text
physical direction = d_c0*q_z
normalized gradient = d_c0*physical gradient
normalized HVP = d_c0*physical HVP(physical direction).
```

The scalar-scalar action therefore has two factors of `d_c0`.  Normalized
quantities never enter the production HVP helper.

## Cache and restoration boundary

The point cache owns one exact normalized scalar key and one production
gradient/HVP result.  The HVP cache owns one exact normalized point/direction
pair and one HVP result.  No evaluation history is accumulated.

Each physical evaluation snapshots every child coefficient, resets scratch,
sets an owned physical coefficient Function, and restores all coefficients in
`finally` before resetting scratch again.  Fixed initial state, target, zero
state direction, and coefficient work values are independent copies.

## Focused test design

scaling algebra, cache eviction/reuse, update handling, input mutation
isolation, success/exception restoration, exact repeatability, injected
active-set margins, PyROL explicit-step derivative utilities, and bounded
L-BFGS optimization wiring.  The optimization smoke is explicitly not HVP
coverage; direct `hessVec` and PyROL Hessian checks instrument HVP calls.

A single module-scoped 2-by-2 serial production fixture supplies the accepted
implementation oracle for:

- normalized value and gradients at one and three complete timesteps;
- normalized HVPs at one and three complete timesteps;
- the explicit `d_c0**2` scalar-block identity; and
- one short centered-gradient ladder whose base/plus/minus active signatures
  are required to match.

The test does not repeat production child-stage forms, reverse ordering,
invariant checks, broad epsilon ladders, or diagnostic classifiers.
